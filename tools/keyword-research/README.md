# keyword-research — измерение реального спроса

Отвечает на вопрос «что аудитория ищет **буквально**», а не «что мы решили, что ей нужно».

## Почему два инструмента, а не один

| Что даёт | Инструмент | Доступ |
|---|---|---|
| **Формулировки** — как люди называют проблему своими словами | `suggest.py` | не нужен |
| **Объём, рунет** — сколько человек в месяц так ищут | `wordstat.py` / ручная выгрузка | нужен |
| **Объём, международный** — точные числа, бесплатно | `bing_kw.py` | ключ Bing Webmaster |
| **Вердикт** — что с этими цифрами делать | `score.py` | не нужен |

Подсказки поисковика строятся на логах реальных запросов. Если фраза есть в подсказках —
её **уже вводят живые люди**. Это не оценка и не гипотеза, поэтому начинать стоит именно
с `suggest.py`: он даёт ответ на исходный вопрос без единого доступа.

## Порядок работы

```bash
# 1. Собрать реальные формулировки (работает сразу)
python suggest.py seeds/masking.txt seeds/152fz.txt --expand --out suggests.csv

# 2. Получить список фраз с операторами для проверки частотности
python wordstat.py suggests.csv --phrases > check.txt
#    → вставить в Вордстат, выгрузить, вписать числа в три колонки CSV

# 3. Вердикт по каждому кластеру
python score.py suggests.csv
```

Когда дадут доступ к API — шаг 2 автоматизируется: заполнить `fetch_frequency()`
в `wordstat.py` по официальной документации и запускать `--api`.

## Международный трек

```bash
# 0. Формулировки. Страна обязательна: язык — не рынок
python suggest.py seeds/masking-en.txt --lang en --country us --expand --out suggests-en.csv

# 1. Точные объёмы бесплатно (Bing Webmaster Tools)
python bing_kw.py --stats suggests-en.csv --country us --language en-US
python bing_kw.py --related "redact before chatgpt" --country us   # расширение кластера

# 2. Вердикт
python score.py suggests-en.csv
```

`bing_kw.py` пишет в те же колонки `wordstat_base` / `wordstat_exact`, что и русский трек
(broad ≈ базовая, strict ≈ точная), поэтому `score.py` читает оба файла одинаково.

**Почему Bing, а не Keyword Planner:** Planner без открученного бюджета отдаёт диапазоны
(«1K–10K»), по которым решение не принять. Bing даёт точные числа бесплатно.

**Оговорка:** доля Bing меньше доли Google, поэтому его абсолютные числа — не твой будущий
трафик. Они годятся, чтобы **ранжировать кластеры между собой**. Настоящие числа Google
покупаются точечно (DataForSEO, ~$0,012 за запрос) только для тех 20–50 фраз, что прошли
бесплатный отбор. Подробности и ловушки — `../../pet-projects/demand-research.md` §6.

**Доступ:** подтверждённый сайт в Bing Webmaster Tools → Settings → API Access → ключ
в `.secrets/bing-webmaster.env` строкой `BWT_APIKEY=...`.

## Доступ к частотности в рунете (на сентябрь 2026)

1. **API Вордстата** — бета, бесплатный, по заявке в поддержку Яндекс Директа. OAuth-токен.
2. **Wordstat в Yandex Cloud Search API** — короткий путь, если облачный аккаунт уже есть.
   У проекта он есть: Yandex AI Studio используется в Unilist (`ai-architecture/`).

Креды — `.secrets/wordstat.env` (gitignored), переменная `WORDSTAT_TOKEN`.

## Операторы — главная ловушка Вордстата

| Запись | Что считает |
|---|---|
| `ремонт окон` | все словоформы **и любые вложенные фразы**. Самая большая и самая лживая цифра |
| `"ремонт окон"` | только эта фраза, словоформы любые |
| `"!ремонт !окон"` | ровно эта формулировка. **Планировать можно только по ней** |

`score.py` считает отношение точной к базовой: если оно ниже 5%, базовая частотность
по кластеру раздута вложенными запросами и опираться на неё нельзя.

## Сиды

`seeds/*.txt` — стартовые фразы по идеям из `../../pet-projects/ideas.md`, разложенные
по трём слоям: проблема → решение → конкурент. Слой важен: запросы слоя «решение»
существуют только там, где категория уже известна рынку.
