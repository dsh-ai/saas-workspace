# Фильтр идей пет-продукта

> Создано: 2026-09-12. Источник требований: формулировка основателя —
> «без особых затрат на поддержку ежедневную и ежемесячную, но чтобы решало одну большую проблему аудитории».

---

## 1. Hard-фильтры (не проходит хотя бы один → идея выбрасывается)

| # | Фильтр | Почему |
|---|---|---|
| H1 | **Ops ≤ 30 мин/нед в стабильном режиме** | Всё остальное — вторая работа, а первая уже есть (Unilist) |
| H2 | **Себестоимость не растёт от бесплатного пользователя** | Либо считаем в браузере, либо BYOK, либо AI только после оплаты |
| H3 | **Одна проблема, один экран** | Если ценность требует схемы для объяснения — это второй SaaS, а не пет |
| H4 | **Ценность видна до регистрации** | У пет-продукта нет бренда, чтобы продавить signup wall. Плюс это прямое правило Show HN |
| H5 | **Артефакт распространяется сам** | Отчёт / ссылка / файл / .ics / бейдж, который пользователь сам отправляет коллеге. Бюджета на трафик нет |
| H6 | **Платит один человек своей картой** | Чек, требующий закупки и демо, требует продавца. Продавца нет |
| H7 | **Есть план смерти** | Продукт можно выключить, не подставив пользователей и себя |

**Тест на H1 (самый важный):** выпиши, что сломается, если ты не откроешь ноутбук 3 недели.
Если в списке есть «упадёт парсер», «протухнет токен», «накопится модерация», «кончится баланс API» —
идея не проходит, как бы красиво ни звучала.

## 2. Антипаттерны — красиво выглядит, дорого живёт

| Архетип | Что убивает |
|---|---|
| Скрейпинг чужой площадки (LinkedIn, маркетплейсы, соцсети) | Ломается неделями, баны аккаунтов, вечная починка |
| Chrome-расширение поверх чужого DOM | Чужой релиз = твой инцидент, плюс ревью стора |
| Мониторинг конкурентов/цен по крону | Кроны + сторонние ключи + алерты «почему не пришло» |
| Чат-обёртка над LLM | Себестоимость на бесплатном юзере не ограничена, дифференциации ноль |
| UGC / каталог / маркетплейс | Модерация и two-sided холодный старт |
| Интеграции с CRM/банком по OAuth | Ротация токенов, «у меня отвалилось» — саппорт навсегда |
| Ты — «источник правды» по живому закону без дисклеймера | Юридическая ответственность за чужую ошибку |
| Realtime / вебсокеты / очереди | SLA, дежурство, наблюдаемость |

## 3. Архетипы с почти нулевым ops (белый список)

1. **One-shot аудит** — вставил URL/файл → получил отчёт → заплатил разово. Нет ретеншена, нет дежурства.
2. **Полностью клиентский инструмент** — вычисления в браузере, бэкенда нет вообще. Себестоимость = статика.
   Бонус: «файл не покидает ваш компьютер» — одновременно фича, маркетинг и отсутствие юрриска.
3. **Данные как продукт** — .ics / JSON / выгрузка, которые обновляются 1–2 раза в год, а не ежедневно.
4. **Генератор артефакта** — заполнил форму → скачал пакет документов. Шаблоны вместо инфраструктуры.
5. **BYOK-инструмент** — пользователь приносит свой API-ключ, ты не платишь за его токены.

## 4. Скоринг (1–5 по каждому, максимум 30)

| Критерий | 1 | 5 |
|---|---|---|
| **Боль** | «было бы неплохо» | стоит денег/штрафов прямо сейчас, есть ручной костыль |
| **Дешевизна ops** | кроны, парсеры, саппорт | статика, обновление раз в квартал |
| **Дистрибуция** | нужен платный трафик | есть готовый канал без бюджета (HN/Reddit/SEO/агентства) |
| **Готовность платить** | «сделайте бесплатно» | уже платят человеку или конкуренту |
| **Низкий риск** | регуляторный/платформенный риск высокий | рисков почти нет |
| **Частота** | разово или раз в год | несколько раз в день |

**Порог:** ≥ 21/30 и ноль провалов по hard-фильтрам — можно тратить выходные.

### 4.1. Про частоту (добавлено 2026-09-12)

Частота — не украшение скоринга, а то, что решает две проблемы сразу: **удержание**
(one-shot аудит имеет нулевой retention по определению — сделал и ушёл) и **дистрибуцию**
(инструмент, открываемый каждый день, попадает в рабочий ритуал и пересылается коллегам сам).

Но с частотой связаны две ловушки:

**Ловушка 1: pull, а не push.** Самый быстрый способ сделать продукт «ежедневным» — послать
пользователю дайджест, алерт или сообщение бота. Это ровно то, что убивает H1: крон, сторонние
ключи, очередь, и вечное «а почему мне не пришло». Настоящая ежедневность — когда пользователь
**сам** открывает вкладку, потому что без неё не может сделать свою работу. Никакой инфраструктуры,
никакого дежурства.

**Ловушка 2: частота бесплатна только в клиентской архитектуре.** Если каждое использование
стоит тебе токенов или запроса к серверу, то ежедневный бесплатный пользователь — это
ежедневный счёт. Ежедневная частота и H2 уживаются только там, где вычисление происходит
в браузере пользователя (или на его ключе).

### 4.2. Инверсия «частота ↔ чек»

Ежедневные инструменты обычно бесплатные утилиты, а дорого платят за редкое и страшное
(разовый аудит под штраф в 20 млн ₽). Это не противоречие, а конструкция:
**частота даёт петлю и привычку, а платит организация за право пользоваться и за правило,
а не пользователь за каждое использование.** Отсюда — корпоративная лицензия вместо
подписки на человека в ежедневных продуктах.

## 5. План смерти (обязателен до первой строки кода)

- Статический инструмент → живёт на CDN вечно бесплатно, «смерть» = просто не трогать. **Лучший вариант.**
- Разовые платные отчёты → закрываешь приём оплат, старые отчёты уже у людей на руках. **Нормально.**
- Подписка с накопленными данными → нужен экспорт, письма, возвраты. **Дорогая смерть — избегать в пете.**

**Kill-criteria фиксируются до запуска**, например: «4 недели после публичного запуска,
< 30 пользователей дошли до результата и 0 оплат → закрываю, не чиню».

## 6. Открытый вопрос, влияющий на выбор дорожки

**Куда принимать деньги от международной аудитории?** Модульбанк закрывает только RU-платежи.
Для Track Global (HN/Reddit/Product Hunt) нужен merchant of record (Paddle / Lemon Squeezy /
Polar) — а он завязан на резидентство и банк основателя (по `Nalog/` — ИП РФ, нерезидент РФ).

Пока вопрос не закрыт:
- **Track RU** можно запускать хоть завтра — эквайринг есть.
- **Track Global** можно запускать в бесплатном виде (трафик, валидация боли), монетизацию откладывать.
